Opensource AI Notetaker - Track and sumarize conversations with an opensource hardware

What is this?

This is a smal opensource device that can record conversations and voice notes, transcribe and sumarize them using AI. 

Introduction and Objectives

With the increasing usage and availability of AI, new possibilities of optimizing our day, our interactions and our way to navigate and explore our world. Some of them become expensive gadjets that can do really simple things. This is one of them. Companies like Plaud.ai[1] and Omi.me[2] charge premmium prices for basic microphones, locked-in tech, and audios that you don't know what happens to them. This project aims to solve this problem by given you open hardware, firmware and app that are completly opensource for the community to develop and maintain, as well as a piece of technology that you own, both the device and what is recorded with it. 

The objectives of this projects are simple:

  1. The device should record, encode and store voice audio, 
  2. The device should be able to send audio to a central location that will transcript and summarize the recording,
  3. The device and the app should own the audio, transcript and summarization, and only share to configured LLM models if the user wants to do so,
  4. The device should have a small size, cheap components and be easily manufacturable on providers such as JLCPCB,
  5. All code and hardware files should remain opensource forever.
  6. The user owns the device, what's recorded and what is done with it.

Hardware

The device core MCU is a STM32WB55REV6 microcontroller, with BLE capabilities and low power options. it features a ton of different GPIO ports, as well as SPI, USART, I2C and I2S communication protocols, as well as alternative functions as LCD driver for example, which is not used on this project. This MCU was chosen because it's a simple microcontroller available almost everywhere, it's cheap, its footprint is fairly small for the qualtity of available functions, and it's one that i'm really used to develop hardware and software to. It's an all-around joker for maker projects, and can handle the recordings well. The BLE capabilities facilitates the inclusion of a wireless module without the addition of a lot of components.

The microphone selected has nothing special. It's a TDK InvenSense ICS-43434. Once again, the selection criteria was availability and price, as well as the use of a I2S communication protocol to pair that with the functions on the STM32WB55REV6.

Peripherals for managing battery charging, connection and power regulation were also carefully selected. You can check the entire schematic (as of Oct-26) below. If you want the updated one, please check the OSHWLab project.

For the PCB design, I've chosen a pill-shaped design that is of simmilar size of some wristband trackers, to try fitting on their silicone bands. This turned out to not be true as these devices use slightly different shapes and sizes, and the range makes it hard to make a one-fit-all design. In the end, i've desinged and 3d printed a band for this device that can also be found on the OSWLab project. 

The PCB uses a 6-layer design. a 4 layer board is theoretcly possible, and I encourage you to try it out if you're a hardware enthusiast, but since JLCPCB 6-layer boards are fairly cheap these days, i've chosen it to be able to have more routing space. The assembly is a one-side-only design and, in my vision, should keep this way. Assembling two-sided boards makes the cost of such device skyrocket, and it's not advisable since this project also aims to be an alternate to the heavy-cost, private ones. 

The manufacturing was done through JLCPCB[3], and costs around $70 per unit already with components and assembled. You can add coupons that JLCPCB offers most of the times, and the cost per unit can drop to around ~$60. Shipping varies a lot, so I'm not adding it here, but that needs to be considered too.


The casing is just a plastic enclosure that holds the 1s 200mhA LiPo together with the PCB and protects the device. I've made mine with transparent resin in JLCPCB to look cool, but less-distractive desings can be achieved (like full white for no detail exposure). In the below view, I've made the front case translucent so you can see the inside on how things are arranged. In the end, that's the beauty of open source: You have the files, yo can manufacture it in any design you want :). The 3D files are also attached to the OSWHLab project, which can be accessed here.

Firmware

The firmware development was done using C, without any HAL layer. I've chosen to do so to have controll of literally everything. HAL layers are good but they bring with them a ton of things that you don't necessarely need in a project. It's the tradeoff if you want portability, which for this project is not necessary. I've also used AI to code most of it, since going by hand on this project would require me a TON of time. The main file (the driver of the STM) called stm32wb55xx.h is the only part of this project that i did most of it by hand. This comes from a different project of mine, and i've spend a lot of time validating the addresses of the microcontroller using the documentation. AI sometimes makes a mess when dealing with microcontroller docs because they use complex formated tables, sometimes including embedded images, to explain the relationship and the address. From my past experience, AI messes up a lot on the parsing of this tables, and take address that are wrong in some cases. 

It is not smart to detail the firmware and it's structure here, since this code is being constantly change (and this article is not). Based on this, you can find the device firmware here.

App

The app was the most interesting part of this development, because it was the first time i've made a native app using AI. Since i've just recently got the iPhone 17, I was curious to experiment a development process that used both an app and it's interaction with a physical device. I've chosen to keep the app simple, and as of the date of this writing, it only works for iOS. I've decided not to develop using an hybrid technology because they have the fame of being slow and broken (could have changed, my last experience is from 2021 or so). Since AI exists and it's fairly cheap now, developing nativelly is the way to go.

For this design, i've chosen to make it functional, while keeping the app easy to maintain, use few screens and straightfoward design. The app is composed by 3 tabs only: 

  • Recordings: Keep the list of your recordings, the details of each, the transcript and sumarizing process, and the sharing logic.
  • Device: Focus on setting things up and managing the details of the physical device, such as uploading new firmware, downloading recordings, a 3D view of the device (because it's damn cool to have one), and some details.
  • Settings: Manage your external model connections, and other basic functionality, details on privacy, as well as let you re-do the onboarding and tutorial.


The app is still in development, and you can find it's code here. I'll be working on an Android version soon so people that have Android phones can also use the device.
